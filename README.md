# VPNDesk

**VPNDesk** — настольное приложение для Windows для импорта, проверки, анализа, сортировки и управления VPN-конфигурациями.

Проект предназначен для удобной работы с большим количеством VPN-конфигураций и источников: от добавления отдельных ссылок до массового импорта, проверки доступности, анализа результатов и формирования отчётов.

VPNDesk разрабатывается с приоритетом на надёжность, безопасность пользовательских данных, производительность и расширяемость.

> **Статус проекта:** активная разработка. Некоторые возможности могут находиться в стадии реализации, тестирования или планирования. Наличие функции в этом описании не означает, что она уже доступна в каждой версии приложения.

## Основные возможности

VPNDesk создаётся как единый центр управления VPN-конфигурациями.

Основные направления развития:

- Импорт конфигураций из разных источников.
- Автоматическое определение поддерживаемых протоколов.
- Проверка синтаксиса и сетевой доступности.
- Проверка реальной работоспособности через совместимый сетевой компонент.
- Проверка доступности выбранных пользователем сервисов.
- Измерение задержки и скорости соединения.
- Сортировка конфигураций по результатам тестирования.
- Поиск и обработка дубликатов.
- Управление источниками и историей изменений.
- Формирование пользовательских отчётов.
- Резервное копирование и восстановление данных.
- Управление дополнительными компонентами.
- Расширение интерфейса с помощью безопасной системы модификаций.

### Интерфейс

Планируемые и развиваемые элементы интерфейса:

- Русский язык по умолчанию.
- Светлая и тёмная темы.
- Главная панель статистики.
- Список конфигураций с поиском и фильтрами.
- Управление источниками.
- Очередь выполняемых задач.
- Подробные результаты проверок.
- Аналитика и рейтинги.
- Настройки производительности.
- История событий и диагностика.

## Поддерживаемые протоколы

VPNDesk ориентирован на работу со следующими протоколами:

| Протокол | Назначение |
|---|---|
| VLESS | Современный прокси-протокол |
| VMess | Протокол экосистемы V2Ray |
| Shadowsocks | Зашифрованный прокси-протокол |
| Trojan | Прокси-протокол с использованием TLS |
| Hysteria2 | Протокол на основе QUIC |
| TUIC | Протокол на основе QUIC |

Фактическая возможность импорта и проверки конкретного типа конфигурации зависит от реализации парсера и доступности совместимого сетевого компонента.

## Импорт конфигураций

Предусматривается несколько способов добавления конфигураций:

- Вставка ссылки.
- Импорт локального файла.
- Вставка текста.
- Импорт из буфера обмена.
- Импорт целой папки.
- Добавление удалённого источника по URL.
- Наблюдение за выбранной папкой.

### Поддерживаемые форматы

- TXT
- JSON
- YAML / YML
- CSV
- ZIP

При импорте приложение должно определять поддерживаемые записи, обрабатывать некорректные данные и выявлять дубликаты.

Для сомнительных записей предусматривается отдельная обработка, чтобы пользователь мог проверить исходный вариант перед исправлением.

Оригинальные файлы не должны изменяться без согласия пользователя.

## Проверка конфигураций

Одна из главных задач VPNDesk — не просто определить наличие конфигурации, а по возможности проверить её реальную работоспособность.

Предусматриваются отдельные уровни проверки:

1. **Синтаксис** — корректность структуры и параметров.
2. **TCP** — доступность сетевого адреса и порта.
3. **Протокол** — проверка подключения через совместимый сетевой компонент.
4. **Сервисы** — доступность выбранных пользователем ресурсов.
5. **Ping** — измерение задержки.
6. **Скорость** — контролируемое измерение производительности соединения.

### Важное различие

VPNDesk не должен считать конфигурацию рабочей только потому, что её TCP-порт отвечает.

Результаты должны различать:

- Синтаксис корректен.
- TCP доступен.
- Протокол успешно проверен.
- Сервис доступен.
- Проверка не выполнена.
- Проверка завершилась ошибкой.

Если необходимый компонент отсутствует или не поддерживает конкретный транспорт, приложение должно сообщить об этом, а не показывать фиктивный результат.

## Рейтинг и аналитика

VPNDesk предусматривает систему оценки конфигураций на основе реальных результатов проверок.

При формировании рейтинга могут учитываться:

- Успешность подключений.
- Ping.
- Измеренная скорость.
- Стабильность.
- Доступность выбранных сервисов.
- Свежесть результатов.
- Количество повторных измерений.

### Категории наград

- 👑 Лучший общий результат.
- 👑 Самая высокая скорость.
- 👑 Минимальный ping.
- 👑 Самое стабильное соединение.
- 👑 Лучший результат по выбранным сервисам.

Награды не должны присваиваться на основании одного случайного измерения или недостаточного количества данных.

Пользователь должен иметь возможность понять, почему конкретная конфигурация получила определённую награду.

## Источники

VPNDesk предусматривает централизованное управление источниками конфигураций.

Для каждого источника планируется хранить:

- Название.
- URL или локальный путь.
- Тип источника.
- Статус.
- Дату добавления.
- Время последнего обновления.
- Количество найденных конфигураций.
- Количество рабочих и нерабочих записей.
- Количество дубликатов.
- Историю изменений.
- Статистику качества.

Предусматриваются операции проверки, обновления, отключения, редактирования, удаления и восстановления предыдущих версий.

Временные сетевые ошибки не должны автоматически приводить к окончательной блокировке источника.

## Управление задачами

Для массовых операций предусматривается система очередей.

Планируемые возможности:

- Запуск и остановка задач.
- Пауза и продолжение.
- Отмена выполнения.
- Приоритеты.
- Ограничение количества проверяемых конфигураций.
- Отображение прогресса.
- Примерное время завершения.
- Журнал выполнения.
- Восстановление незавершённых задач после сбоя.

Проверка источников и проверка отдельных конфигураций рассматриваются как разные типы задач.

Пользовательские ограничения должны соблюдаться строго: если установлен предел в 500 конфигураций за цикл, приложение не должно проверять 501-ю.

## Отчёты и экспорт

Формирование отчётов должно выполняться только по инициативе пользователя.

VPNDesk не должен самостоятельно отправлять результаты проверок, создавать GitHub Issues или публиковать диагностические сведения.

Предусматриваются следующие варианты:

- Полный TXT-отчёт.
- Отдельный TXT со списком рабочих конфигураций.
- Отдельный TXT со списком нерабочих конфигураций.
- Настраиваемый отчёт.
- JSON.
- CSV.

В отчёте могут отображаться:

- Общее количество конфигураций.
- Количество проверенных.
- Количество рабочих и нерабочих.
- Используемые протоколы.
- Источники.
- Доступность выбранных сервисов.
- Ping.
- Измеренная скорость.
- Причины ошибок.
- Рейтинг и награды.
- Дата и время проверки.

Добавление самих VPN-ссылок в отчёт должно быть отдельной настройкой с предупреждением: конфигурации могут содержать секретные ключи и другие данные доступа.

## Безопасность и конфиденциальность

Безопасность пользовательских данных — один из приоритетов проекта.

Основные принципы:

- Не отправлять конфигурации на сторонние серверы без явного действия пользователя.
- Не публиковать отчёты автоматически.
- Не записывать секретные части конфигураций в обычные логи.
- Не хранить секреты в открытом виде в базе данных.
- Использовать подходящие системные механизмы защиты секретов Windows.
- Проверять импортируемые архивы и файлы.
- Защищаться от Zip Slip и Path Traversal.
- Не запускать исполняемые файлы из импортированных архивов.
- Проверять целостность обновлений.
- Создавать резервные копии перед опасными операциями.
- Не изменять системные маршруты, DNS и VPN-настройки Windows.

### Локальная обработка

Основная база конфигураций и история приложения предназначены для локального хранения.

Сетевые запросы выполняются для операций, которые требуют доступа к источникам, проверки соединений, загрузки компонентов или получения обновлений.

Пользователь должен понимать, какие действия выполняются и какие данные передаются во внешнюю сеть.

## Системные требования

VPNDesk разрабатывается для Windows.

### Рекомендуемая среда

- Windows 10 или Windows 11.
- Современный процессор x64.
- 4 ГБ оперативной памяти или больше.
- Достаточное свободное место для базы данных, истории и резервных копий.
- Подключение к интернету для сетевых проверок и обновления источников.

Фактические требования зависят от количества одновременно проверяемых конфигураций, выбранного профиля нагрузки и используемых компонентов.

Для слабых компьютеров предусматривается облегчённый профиль с ограничением параллельных задач.

## Установка и запуск

### Вариант 1. Готовая сборка

Если для версии опубликована проверенная Windows-сборка:

1. Откройте раздел Releases.
2. Скачайте архив или установщик нужной версии.
3. Распакуйте архив, если используется portable-вариант.
4. Запустите приложение.

Скачивайте файлы только из официального репозитория проекта или другого источника, которому доверяете.

### Вариант 2. Запуск из исходников

Для запуска из исходного кода потребуется Python подходящей версии.

Клонирование репозитория:

```bash
git clone <URL-РЕПОЗИТОРИЯ>
cd VPNDesk
```

Создание виртуального окружения:

```bash
python -m venv .venv
```

Активация в Windows:

```bat
.venv\Scripts\activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Запуск:

```bash
python main.py
```

Если точка входа или способ установки отличаются в конкретной версии, используйте инструкции, расположенные в соответствующих файлах проекта.

## Тестирование

В проекте предусматривается автоматический набор тестов.

Основные направления:

| Тип тестов | Что проверяется |
|---|---|
| Unit tests | Парсер, база, кэш, рейтинги, отчёты и очереди |
| Integration tests | Импорт, источники, экспорт, резервирование и восстановление |
| Stress tests | Большие файлы, тысячи конфигураций и массовые задачи |

| UI tests | Навигация, страницы, диалоги, фильтры и основные действия |

Запуск тестов:

```bash
python -m unittest discover -s tests -v
```

Если в конкретной версии используется другая тестовая система, способ запуска указывается в документации этой версии.

Результаты тестирования должны отражать только реально выполненные проверки. Пропущенные тесты не считаются успешными.

VPNDesk является программным инструментом для работы с VPN-конфигурациями. Приложение не предоставляет собственную VPN-инфраструктуру, серверы или подписки.

Пользователь самостоятельно отвечает за:

- Законность использования конфигураций и сетевых ресурсов.
- Наличие разрешения на использование сторонних источников.
- Соблюдение законодательства своей страны.
- Соблюдение правил сторонних сервисов.
- Проверку происхождения импортируемых файлов и ссылок.
- Защиту собственных ключей и конфигураций.
- Решения о публикации и передаче результатов проверок.

VPNDesk не гарантирует анонимность, безопасность, доступность или работоспособность сторонних VPN-серверов.

Программа предоставляется «как есть» в пределах условий выбранной лицензии и применимого законодательства.
