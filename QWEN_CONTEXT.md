## Обязательные правила
1. Сначала прочитай README, это руководство, полное ТЗ, исходный README и AUDIT REPORT.
2. Исследуй существующий код 0.4.0. Не начинай с переписывания проекта с нуля.
3. Сохрани исходный архив как неизменяемую точку возврата.
4. Составь карту проекта: файлы, точки входа, зависимости, БД, UI, потоки, импорт, парсер, проверки, отчёты, компоненты, тесты.
5. Проведи собственный аудит; старый отчёт не является гарантией.
6. Сохраняй исправные функции и пользовательские данные. Не удаляй функции без обоснования.
7. Не создавай заглушки, фиктивные проверки и вымышленные результаты тестов.
8. Перед изменениями БД предусматривай миграции и резервные копии.
9. Обновляй `DEVELOPMENT_STATUS.md` и `CHANGELOG_RU.md` по мере работы.
10. Всегда указывай, что реализовано, проверено, не проверено и какие ограничения остались.
11. Не заявляй о проверке Windows GUI/EXE, если запускался только Linux.
12. Не публикуй реальные VPN-ключи, подписки, токены, пароли и личные конфигурации.

## Технологии 0.4.0
Python 3.11+, PySide6, SQLite, keyring, psutil, sing-box как внешний компонент, PyInstaller для Windows-сборки. Сверяйся с requirements.txt и фактическим кодом.

## Проверки
Поддерживаются направления VLESS, VMess, Shadowsocks, Trojan, Hysteria2 и TUIC. Различай синтаксис, TCP, реальную проверку через sing-box, сервисный HTTPS-запрос, ping и измеренную скорость. TCP-ответ **не означает**, что VPN работает. Отсутствующий компонент или неподдерживаемый транспорт не должны давать фиктивный успех.

## Ограничения исходного аудита
Не были подтверждены Windows GUI/DPI/трей/EXE и живой сетевой прогон sing-box. Некоторые нестандартные транспорты и плагины не поддерживаются; часть обновления, восстановления и многозадачности не завершена. Наличие функции в README или ТЗ не доказывает её реализацию.

## Тесты
Для исходного архива повторно выполнено: `python -m compileall -q .` — успешно; `python -m unittest discover -s tests -v` — 31 тест пройден. Это не подтверждает Windows GUI, EXE и реальные сетевые проверки.

## Безопасность
Не логируй секретные части URI; не храни токены открыто; защищай ZIP-импорт от Zip Slip/path traversal/архивных бомб; не запускай код из импортированных архивов и модов; не меняй маршруты/DNS Windows; отчёты публикуются только по инициативе пользователя. Тестовые данные должны быть фиктивными.

Начинай развитие только после изучения реального кода 0.4.0. Приоритеты: надёжность, корректность данных, безопасность, производительность на слабых ПК, русский интерфейс, тестируемость и расширяемость.
